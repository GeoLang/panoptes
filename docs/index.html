👁️ Panoptes

AI feature extraction from geospatial imagery: segmentation and change analysis. Pure Rust, GDAL-free.

Experimental. Building segmentation weights are published as a release asset you download; roads, landcover, vegetation and change have none, so for those you supply an ONNX model and pass it with --model path/to/model.onnx. Model weights.

Features

🧠 Semantic Segmentation

  • Per-pixel classification
  • Multi-class output with confidence, in the engine only: the CLI configures any --model as two-class, so classes 2..K are dropped
  • ONNX Runtime inference, needing --features onnx and a system libonnxruntime. The release workflow builds without the feature, so published binaries cannot run ONNX
  • User-supplied .onnx model
  • Threshold heuristic for smoke tests

🛰️ Satellite Preprocessing

  • DN to top-of-atmosphere reflectance
  • DOS1 atmospheric correction
  • Brovey pan-sharpening
  • NDVI, NDWI, EVI, NBR, SAVI indices
  • Band compositing
  • Library only and unreachable: nothing constructs a SatelliteImage, and the file reader converts every image to 3-channel 8-bit RGB, so no NIR or SWIR band can enter. The Sensor enum carries no calibration coefficients

🔄 Change Detection

  • Temporal image comparison
  • Pixel differencing, not a model
  • Change magnitude scoring
  • Single scale, no pyramid
  • GeoJSON change polygons

🖼️ Tiled Processing

  • Sliding window with overlap
  • Configurable tile size
  • Whole tiles only, edge remainders dropped
  • Tiling bounds the model input, not memory: the whole image is decoded to a full-size f32 array first

📐 Vector Output

  • Automatic polygonization, one traced pixel-edge outline per connected component, holes filled
  • GeoJSON export
  • class_id, area_px, confidence properties
  • Pixel-space coordinates, no CRS yet

📊 Quality Metrics

  • Intersection over Union (IoU)
  • Mean IoU across classes
  • Pixel accuracy scoring
  • Per-polygon confidence from the model
  • Evaluation against ground truth

☁️ Cloud Optimized GeoTIFF

  • TIFF IFD and tile offset parsing
  • Overview pyramid levels
  • A tile read returns raw undecoded bytes: no decompression, no pixel decode
  • Local files only, no HTTP or S3 client
  • No geotransform parsing yet
  • Unreachable from the CLI, which loads images through the image crate instead

🔀 Parallel Processing

  • Tile-parallel inference via rayon
  • Result aggregation across tiles, blending the overlap
  • Configurable tile size and overlap
  • Single process, not a cluster
  • Library only, no CLI command: the CLI runs a sequential map that polygonizes each tile on its own

🔍 Explainability

  • Occlusion sensitivity maps
  • Saliency map from confidence
  • Per-pixel confidence maps
  • Heatmap overlay on the source image
  • Library only, no CLI command

Catalog Models

Building weights are published as the panoptes-buildings-v1.onnx asset of the weights-buildings-v1 release, downloaded into the working directory. The other entries hold metadata only, input size, classes and thresholds, so naming one falls back to the threshold heuristic. Pass --model path/to/model.onnx to run your own segmentation model.

Quick Start

# Segment buildings, with panoptes-buildings-v1.onnx downloaded into this directory
panoptes segment --input image.tif --output buildings.geojson --model buildings

# Or segment with your own ONNX model
panoptes segment --input image.tif --output out.geojson --model path/to/model.onnx

# Detect changes between two dates
panoptes change --before 2022.tif --after 2024.tif --output changes.geojson

# List catalog models and where their weights come from
panoptes models

# Evaluate prediction accuracy
panoptes evaluate --prediction pred.tif --ground-truth gt.tif --num-classes 5
